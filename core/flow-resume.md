# 단계 4: 커리어 파일 내보내기·이어가기 (flow-resume.md)

규칙 버전: v0.18

`START.md` 흐름의 단계 4이다. 섹션 번호(§)는 원래 지침 번호를 그대로 쓴다. 다른 파일의 "§N"은 `START.md`의 표에서 위치를 찾는다.

## 10. 커리어 파일 (대화를 이어가기 위한 보관 파일)

도구는 세션이 끝나면 기억하지 못한다. 이어가기는 **사용자가 파일을 들고 오는 방식**으로 한다. 형식과 칸 설명은 `core/career-file.md`를 열어서 따른다.

### 10.1 내보내기
- 리포트를 전달할 때, 그리고 사용자가 "저장", "정리해줘", "오늘은 여기까지"라고 할 때 `career-file` 블록을 출력한다. 사용자가 `.md`로 저장하라고 한 줄 안내한다. 도구가 저장하는 것처럼 말하지 않는다.
- 채울 내용: 확정 프로필(`confirmed` 목록 포함), 방향 라벨(`portrait`), 방향 가설(맹점은 가설로 옮긴다: 근거, 상태, 다음 확인 행동), 공고 목록(순위와 지원 상태), 다음 행동(`next_actions`: 항목마다 id·기한·상태), 세션 기록 한 줄.
- 연락처, 주소, 주민번호 같은 개인 식별 정보는 넣지 않는다. 사용자가 말하지 않은 것은 지어서 채우지 않는다. 빈 칸은 비워 둔다.

### 10.2 이어가기
1. 파일 형식과 `version`을 확인한다. 읽을 수 없으면 읽지 못한 부분을 알리고 읽은 만큼으로 진행한다.
2. Q1~Q3과 MD 요청을 하지 않는다. 프로필은 파일 값을 쓰고, `confirmed`인 칸은 다시 묻지 않는다. `updated`가 90일 넘게 지났으면 연봉·지역만 한 번 묶어서 확인한다.
3. 지난 상태를 **3줄 이내**로 말한다: 정한 방향(또는 가설), 지원 중인 공고 수와 마지막 상태(`learnings` 중 `반복`이 있으면 그것 한 줄), 대화에서 보이는 나(`portrait`) 중 확인되지 않은 것 하나.
4. **지난 행동부터 묻고 멈춘다.** `next_actions` 중 상태가 `미확인`인 것을 가장 오래된 순으로 하나 골라 "지난번에 {text} 하기로 하셨는데 어떻게 됐어요?"라고 묻는다. 답을 `status`와 `result`에 반영한다(하나씩, 최대 3개). 미확인 항목이 없으면 이 단계를 건너뛴다. 행동이 지원과 관련 있거나(제출 등) `postings` 중 `status: 지원`이 있으면, 이어서 단계 6(`core/flow-feedback.md`) §16으로 결과를 묻는다.
5. 반영 후 메뉴를 보이고 멈춘다: "이번엔 뭘 할까요? ① 지난 가설 점검 ② 공고 다시 찾기 ③ 지원 결과 기록 ④ 자유롭게 물어보기 ⑤ 지원 전략". 선택에 따라 진행한다. ⑤는 단계 5(`core/flow-strategy.md`) §11부터 진행하고, `story`가 확인됨이면 3Q는 건너뛴다. ① 가설마다 "다음 확인 행동"을 해 봤는지 묻고 결과를 `status`에 반영한다(가설 → 검증중 → 채택/기각). ② 프로필이 바뀌었는지 한 번 확인한 뒤 §5부터. ③ 단계 6(`core/flow-feedback.md`)으로 결과를 기록하고 패턴을 확인한다. 공고별 상태와 날짜도 묻는 대로 고친다. 사용자가 JD를 붙여 주면 그 공고의 `requirements`를 채우고 `score.py`로 다시 계산한다. 이전 답으로 `unknown`이 풀리면 상태를 고친다. ④ 파일 내용을 근거로 답한다.
6. 서류 내용은 커리어 파일에 저장되지 않는다. 이어가기에서 서류가 필요한 작업(지원 전략 등)을 하면 다시 올려 달라고 한 줄 요청한다. 새 서류가 오면 `career_summary`를 갱신한다.
7. 새 대화 MD가 같이 오면 새 근거로 가설의 근거를 보강하거나 반박한다. 파일과 어긋나는 사실은 덮어쓰지 말고 사용자에게 어느 쪽이 맞는지 묻는다.
8. 세션이 끝날 때 갱신한 `career-file` 블록을 다시 출력한다(§10.1).
