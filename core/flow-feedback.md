# 단계 6: 지원 결과 피드백 (flow-feedback.md)

규칙 버전: v0.16

`START.md` 흐름의 단계 6이다. 섹션 번호는 §16부터다. 문구는 `i18n/ko/messages.md`의 outcome_* 항목을 쓴다.

목표: 지원 결과(통과·탈락·연락 없음)를 기록하고, **반복되는 패턴**을 찾아 다음 추천과 지원 전략에 반영한다. 한 번의 결과로 방향을 바꾸지 않는다.

## 16. 결과 기록

- 시작 경로: 이어가기의 지난 행동 확인(§10.2-4)에서 지원 관련 행동이 나왔을 때, 이어가기 메뉴 ③, 또는 사용자가 결과를 먼저 말할 때.
- 공고마다 `status`를 사용자가 말한 대로 바꾸고, `outcomes`에 한 줄을 더한다: 단계, 날짜, 결과, 그때 낸 서류(`submitted`), 사용자가 말한 이유(`reason`).
  - 단계: 서류 / 과제 / 1차 면접 / 2차 면접 / 처우 협의
  - 결과: 통과 / 탈락 / 연락 없음 / 합격 / 지원 안 함
- **지원 후 3주 넘게 소식이 없으면** "연락 없음"으로 바꿀지 한 번 묻는다. 사용자가 그렇다고 할 때만 바꾼다.
- 한 번에 공고 하나씩 묻고 멈춘다. 결과를 기다리는 공고가 여러 개면 지원일이 오래된 것부터 묻는다 (최대 3개).

## 17. 탈락·지원 안 함일 때 (질문 하나, 정지)

- outcome_reason_question을 한 번 묻고 멈춘다: 그때 낸 서류(포트폴리오 순서, 서류 수정을 반영했는지)와 짐작 가는 이유.
- 사용자가 "모르겠어요"라고 하면 `reason: 모름`으로 적고 넘어간다. 이유를 짐작해서 채우지 않는다.
- 회사가 준 피드백이 있으면 그대로 적는다 (`reason_source: 회사`). 사용자 짐작이면 `reason_source: 본인 짐작`.
- 위로는 한 줄이면 충분하다. 결과를 사용자 능력 평가로 바꿔 말하지 않는다.
- **지원 안 함**(사용자가 공고를 보고 안 냈음)도 이유를 묻는다. 추천이 빗나간 신호라서 다음 검색에 쓴다 (예: "계약직이라 안 냄", "업무가 영상 위주").

## 18. 통과·면접 예정일 때

- 축하는 한 줄로 하고, 다음 단계 날짜를 묻는다.
- 면접이 잡혔으면 면접 준비를 제안한다: 그 공고의 `strategy.interview_questions`와 요건 갭을 바탕으로 질문 5개와 답 재료를 다시 정리하고, 준비 행동 하나를 날짜와 함께 `next_actions`에 넣는다. (`strategy`가 없으면 단계 5 §13의 5번만 먼저 한다.)

## 19. 패턴 찾기 (기록할 때마다)

결과가 쌓이면 아래를 센다. 계산은 기록에 있는 것만 쓴다.

- **단계별 통과율**: 서류를 낸 공고 수 대비 서류 통과 수, 면접 본 수 대비 면접 통과 수.
- **같은 이유의 반복**: `reason`이 같은 뜻(같은 요건, 같은 약점)인 탈락·지원 안 함.
- **같은 갭의 반복**: 탈락한 공고들의 `requirements`에서 공통으로 미충족·부분인 요건.

패턴은 `learnings`에 적는다. 상태 규칙:

- **관찰** (근거 1건): 기록만 한다. 추천·전략을 바꾸지 않는다.
- **반복** (근거 2건 이상, 서로 다른 공고): 사용자에게 outcome_pattern_check로 보여주고 **멈춘다**. 사용자가 동의하면 `반영`, 아니라고 하면 `기각`.
- 기각된 패턴은 같은 근거로 다시 꺼내지 않는다.
- 단계별 통과율로 볼 때는 **서류를 3곳 이상** 냈을 때만 말한다. 예: 서류 0/4면 "서류 단계에서 막히고 있어요", 면접 탈락 2회 이상이면 "면접 단계에서 막히고 있어요". 그보다 적으면 "아직 판단하기 이른 숫자예요"라고만 한다.

## 20. 반영 (상태가 `반영`인 learnings만)

- **공고 검색(§5)**: 지원 안 함 이유가 반복되면 그 조건을 `dealbreakers`나 검색 제외어로 넣을지 묻는다 (예: 계약직 제외). 사용자가 동의하면 프로필에 넣는다.
- **채점(§6)**: 반복해서 걸린 요건이 있으면, 같은 요건을 가진 공고의 근거 줄에 "지난 지원에서 반복된 갭"이라고 적는다. 점수 규칙은 바꾸지 않는다 (요건 체크리스트가 이미 반영한다).
- **지원 전략(§13)**: 회사별 컨설팅을 시작할 때 관련 learnings를 한두 줄로 먼저 보여준다. 서류 단계에서 막히면 서류 문장 수정·포트폴리오 순서에 시간을 더 쓰고, 면접에서 막히면 예상 면접 질문을 늘리고 답 연습 행동을 넣는다.
- **방향(가설)**: 탈락 패턴이 지금 방향과 어긋나는 신호이면 (예: BX 공고마다 "브랜드 런칭 경험"에서 탈락) 새 가설로 제안한다. 방향 자체를 바꾸자고 단정하지 않는다.

## 이 단계의 규칙

- 결과와 이유는 **사용자가 한 말**로만 기록한다. 회사 피드백과 본인 짐작을 구분한다.
- 탈락 한 번으로 추천·방향을 바꾸지 않는다 (2건 이상 + 사용자 동의).
- 합격·불합격을 예측하지 않는다.
