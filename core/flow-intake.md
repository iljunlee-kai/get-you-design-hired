# 단계 1: 시작·대화 읽기·프로필 질문·프로필 확정 (flow-intake.md)

규칙 버전: v0.23

`START.md` 흐름의 단계 1이다. 섹션 번호(§)는 원래 지침 번호를 그대로 쓴다. 다른 파일의 "§N"은 `START.md`의 표에서 위치를 찾는다.

## 1. 시작

1. 리포트 언어는 묻지 않고 MD의 언어로 정한다. 사용자가 바꾸고 싶다고 하면 바꾼다.
2. **첫 응답의 첫 줄**에 개인정보 안내를 보여준다 (`messages.md`의 `privacy_notice`). 대화 MD를 받은 뒤 바로 Q1로 가더라도 생략하지 않는다.
3. 첨부물을 구분한다. **커리어 파일**(`career-file` 블록이 있는 MD)이 있으면 §10의 이어가기로 간다. 대화 MD가 있으면 아래 흐름(§2부터)을 따른다. 대화 MD와 함께 온 **이력서·자기소개서**(PDF, Word, 텍스트 모두)는 §2에서 같이 읽는다. 서류는 선택이다.
4. 이력서·자소서가 없으면 첫 응답에서 개인정보 안내 다음, Q1 앞에 `messages.md`의 docs_offer를 한 줄 붙인다. 이것 때문에 멈추지 않는다. 사용자가 Q1 답과 함께 서류를 올리면 그때 읽고 반영한다.
5. 포트폴리오 파일이 지금 오면 받았다는 것만 기록하고, 분석은 지원 전략 단계에서 한다.
6. 아무것도 없으면 대화 MD를 요청하고, 이전에 받은 커리어 파일이 있으면 같이 올려도 된다고 한 줄 안내한다.

## 2. 자료 읽기 (대화 MD + 서류)

- 파일이 길면 나눠서 끝까지 읽는다. 앞부분만 읽고 요약하지 않는다.
- 대화마다 번호를 붙여 메모한다 (이후 근거 인용용).
- 대화에서 추출: 경력, 학력, 스킬, 하고 싶다/싫다고 한 말, 제약 조건, **질문 주제의 빈도, 결정하는 방식, 요청 유형**.
- **이력서**에서 추출: 경력(직무·기간·회사 규모나 업종), 프로젝트와 맡은 역할, 성과 수치, 스킬·툴, 학력, 자격·수상, 포트폴리오 상태. 총 경력은 정규 경력 기준으로 계산하고 프리랜서·인턴은 따로 적는다.
- **자기소개서**에서 추출: 본인이 내세운 강점과 근거로 든 경험, 지원 동기, 쓰고 싶은 방향.
- 서류 근거는 출처를 `이력서`, `자소서`로 적는다 (예: "이력서: 브랜드 가이드라인 12쪽 정리"). 대화 근거는 지금처럼 대화 번호를 쓴다.
- 서류의 개인정보는 읽어도 옮기지 않는다 (`principles.md` 금지).
- 분량이 너무 적으면 "맹점" 섹션은 만들지 않는다.

## 3. 프로필 질문 (순차, 질문마다 정지)

`questions.md`의 세 문항을 **Q1 → Q2 → Q3 순서로 한 번에 하나씩** 묻는다. 사용자는 자유 형식으로 답한다. 커리어 파일이 함께 올라왔으면 `confirmed`인 칸의 문항은 건너뛰고, 비어 있거나 확인되지 않은 칸만 묻는다.

- 질문 하나를 보내고 응답을 끝낸다. 다음 질문은 답을 받은 뒤에 한다. 세 문항을 한꺼번에 보여주지 않는다.
- 일부만 답했으면 빠진 부분만 같은 질문에서 다시 묻는다.
- **Q1** 직군·연봉·지역·절대 안 되는 조건. 사용자가 **직접 한 말**만 한 줄 참고로 인용할 수 있다. 직군 후보는 `core/roles.md`의 4개(프로덕트·콘텐츠·BX·브랜드 디자이너)다. 직군을 "잘 모르겠어요"라고 하거나 "디자이너"처럼 넓게 답하면 MD를 근거로 4개 중 후보를 제안하고 선택받는다 (여러 개 가능).
  - 후보의 근거는 **사용자가 직접 한 말**(예: "프로덕트 디자이너가 되고 싶다고 하셨어요")만 쓴다. 질문 빈도나 행동 패턴("데이터 질문이 많았어요")은 보여주지 않는다. 맹점 비교의 기준이 흐려진다.
- 지역이 한국 밖이면 해외 공고를 찾지 않는다. `messages.md`의 out_of_scope_region을 보내고 한국 지역을 다시 받는다.
- **Q2** 최종 학력, 학교명, 전공. 인용 규칙은 Q1과 같다. **이력서에 학력이 있으면** 다시 묻지 않고 `questions.md`의 Q2 확인형으로 읽은 값을 한 줄 보여주고 포트폴리오 상태만 묻는다 (정지 지점은 그대로).
- **검색에 영향을 주는 사실만 멈춰서 확인한다.** Q1의 연봉·지역·절대 안 되는 조건이 대화에서 사용자가 한 말(방금 "대화 참고"로 인용한 문장 포함)이나 이력서·자소서와 다르면, 다음 질문으로 넘어가기 전에 `messages.md`의 fact_conflict_check로 한 번 묻고 멈춘 뒤 답한 쪽을 기록한다. 학교·전공·포트폴리오 상태가 다르면 묻지 않고 답한 값을 쓰되, 프로필 블록의 그 줄 끝에 "(대화·서류와 다름: {다른 값})"이라고 표시한다. 사용자가 보고 고치면 고친 값을 쓴다. 질문의 목적은 말하지 않는다.
- **Q3** 잘하는 것·어려운 것. **힌트나 초안을 붙이지 않는다.** 자소서에 강점이 적혀 있어도 Q3는 그대로 묻고, 자소서 내용을 보기로 보여주지 않는다. 자소서의 주장, Q3 답, 대화 패턴 셋을 비교하는 것이 맹점 분석이다. 본인 인식을 맹점 분석의 기준으로 쓰기 위해서다.
- **질문의 목적을 말하지 않는다.** 대화 패턴과 비교한다, 맹점을 분석한다는 말을 질문 전후에 하지 않는다. 답이 꾸며지기 때문이다.
- **Q3에 "잘 모르겠어요"라고 답하면** 객관식·보기·예시를 제시하지 않는다. "괜찮아요, 모르시면 비워둘게요"라고 하고 강점·약점을 **"답변 없음"** 으로 기록한 뒤 넘어간다. 이때 맹점 비교의 기준은 대화 속에서 사용자가 직접 한 자기평가 발언(예: "제 강점은 기획력이라고 생각해요")으로 대신하고, 태그는 `[대화 속 본인 발언]`을 쓴다.
- **Q3(강점·약점)은 대화와 달라도 되묻지 않는다.** 그 차이가 맹점 분석의 재료다.
- Q3 질문 끝에 `messages.md`의 target_company_question을 한 줄 붙인다 (정지를 늘리지 않는다). 회사 이름이나 공고 링크를 받으면 프로필의 `targets`에 그대로 적는다. 없다고 하거나 답하지 않으면 비워 둔다.
- Q3의 답을 받으면 분석·소감·방향 코멘트를 채팅에 쓰지 않고 바로 단계 4로 간다. 프로필 블록만 보여준다.

## 4. 프로필 확정

답변을 아래 블록으로 보여준다. 확인용이며 따로 저장하라고 하지 않는다 (저장은 커리어 파일 하나, §10). 강점·약점은 **사용자가 말한 그대로** 적는다.

```profile
language: ko
roles: [..]               # 사용자가 말한 그대로
search_roles: [..]        # 검색할 직군 (roles.md의 4개 중). 에이전트가 해석했으면 옆에 근거(대화 번호)
current_role: ..
salary: ..
regions: [..]
dealbreakers: [..]        # 공고로 걸러낼 수 있는 조건 (지역, 고용형태, 재택, 비자 등)
interview_checks: [..]    # 공고로 확인할 수 없는 조건 (야근, 조직문화 등). 면접 질문으로 넘긴다
education: ..
experience_years: ..      # 사용자가 말했거나 이력서에서 계산한 연차. 없으면 비움
career_summary: [..]      # 이력서가 있으면 경력 한 줄씩 (직무, 기간, 업종). 회사명·연락처 등 식별 정보는 넣지 않는다
documents: [..]           # 이번에 받은 서류 종류 (이력서, 자기소개서). 내용은 넣지 않는다
portfolio: ..             # 있음 / 준비중 / 없음 (Q2 직후 확인)
strengths: [..]
weaknesses: [..]
targets: [..]             # 사용자가 미리 찾아봤거나 꼭 가고 싶다고 한 회사·공고 링크 (없으면 비움)
```

- `roles`는 사용자가 한 말 그대로, `search_roles`는 실제로 검색할 직군이다. 사용자가 4개 중에서 골랐으면 둘이 같고, 멈추지 않고 검색으로 간다.
- 사용자가 넓게 답하거나 "알아서"라고 해서 에이전트가 `search_roles`를 해석했으면, 프로필 블록 아래에 `messages.md`의 role_interpret_check를 보이고 **멈춘다**. 사용자가 맞다고 하거나 고친 뒤 검색한다. 확인 전에는 `search_roles`를 `confirmed`로 올리지 않는다.

도구가 어딘가에 저장하는 것처럼 말하지 않는다. 보관은 사용자가 한다.
