# ChatGPT(커스텀 GPT)로 쓰기

> 2026-10-25부터 커스텀 GPT 경로는 지원하지 않는다. 이 문서의 "저장 후 확인" 순서는 Claude에서 레포를 직접 읽어 테스트할 때 그대로 쓴다.

GPT는 이 레포를 **직접 읽는다**. 지침 칸에는 시작 방법만 넣고, 실제 지침은 레포의 `START.md`부터 따라간다. 그래서 레포를 고치면 GPT를 다시 올리지 않아도 바로 반영된다. `main` 브랜치에 push하는 순간 사용 중인 GPT에도 적용되니 push 전에 확인한다.

## 1. 지침
`gpt/instructions.txt` 전체를 복사해 **지침(Instructions)** 칸에 붙여넣는다. 이전 지침은 지운다.

## 2. 지식(Knowledge) 파일
기본은 **올리지 않는다** (레포를 직접 읽는다). 레포 접근이 막힐 때를 대비하려면 아래를 올려 둘 수 있다. 이 경우 수정할 때마다 다시 올려야 하고, 올린 파일이 오래되면 레포와 어긋난다.

`START.md`, `core/principles.md`, `core/flow-*.md` 6개, `core/roles.md`, `core/ice-rubric.md`, `core/career-file.md`, `core/score.py`, `sources.yml`, `i18n/ko/questions.md`, `i18n/ko/messages.md`, `i18n/ko/report.md`, `i18n/ko/strategy-questions.md`

## 3. 기능
- 웹 검색: 켜기 (레포 읽기와 공고 검색에 필요)
- 코드 인터프리터: 켜기 (점수 계산과 DOCX 생성에 필요)

## 4. 대화 시작 문구
"AI와 나눈 대화 MD를 올릴게요"

## 5. 저장 후 확인
0. 새 대화에서 "START.md를 읽었으면 마지막 줄을 그대로 적어줘"라고 보낸다. `<!-- END: START.md -->`가 나와야 한다.
1. 새 대화에서 `examples/sample-conversation.md`를 올린다.
2. 개인정보 안내 한 줄이 나오고 Q1만 묻고 멈추는지 확인한다.
3. Q1에 한국 밖 지역(예: 뉴욕)을 답하면 "지금은 한국 공고만 찾을 수 있어요" 안내가 나오는지 확인한다.
4. Q3에 "잘 모르겠어"라고 답하면 보기를 제시하지 않고 넘어가는지 확인한다.
5. 리포트 끝에 `career-file` 블록이 나오는지 확인한다. 그 블록을 `커리어파일.md`로 저장한다.
6. 새 대화에서 저장한 `커리어파일.md`만 올린다. Q1~Q3 없이 지난 상태 3줄 요약이 나오고, **지난 행동("지난번에 ~ 하기로 하셨는데 어떻게 됐어요?")을 먼저 묻고 멈추는지** 확인한다. 답한 뒤 ①~④ 메뉴가 나오는지 본다.
7. 디자이너 테스트: `examples/sample-conversation-designer.md`를 올린다. 포트폴리오 상태 질문이 나오는지, 총평 아래에 "대화에서 보이는 당신은 ~" 라벨이 근거(대화 번호 2개 이상)와 함께 나오는지, 질문이 문구·화면 흐름 쪽으로 쏠린 것이 맹점으로 잡히는지 확인한다.
8. 커리어 파일을 열어 `profile.confirmed`와 `portrait`, `next_actions.status`가 채워졌는지 본다. 다음 세션에서 `confirmed`인 값을 다시 묻지 않는지 확인한다.

9. 서류 테스트: `examples/sample-conversation-designer.md`와 함께 `sample-resume-designer.md`, `sample-cover-letter-designer.md`를 올린다. Q2가 확인형(이력서에서 읽은 학력 + 포트폴리오 질문)으로 나오는지, Q3에 자소서 내용이 보기로 나오지 않는지, 리포트에 "서류 점검" 표가 있는지, 이름·연락처가 리포트와 커리어 파일 어디에도 없는지 확인한다.

10. 지원 전략 테스트: 9번에 이어 리포트가 나오면 1~3위 중 하나를 고른다. 3Q가 초안(근거 포함)과 함께 하나씩 나오는지, 요건 확인 질문이 하나씩 나오는지, `examples/sample-portfolio-designer.pdf`를 올렸을 때 본 페이지를 밝히고 시각적 완성도를 평가하지 않는지, 마지막에 "언제 하실래요?"로 날짜를 받는지, 커리어 파일에 `story`와 `strategy`가 들어가는지 확인한다. 이미지 전용 PDF(`sample-portfolio-designer-image-only.pdf`)로도 한 번 해 본다.

11. 지원 결과 테스트: 새 대화에서 `examples/sample-career-file-designer.md`만 올린다. 지난 행동(지원 제출)을 먼저 묻는지, 이어서 공고별 결과를 하나씩 묻는지 본다. 이렇게 답해 본다: P1 서류 탈락(이유 모름), P2 서류 탈락("런칭 경험이 없어서인 듯"), P3 지원 안 함("계약직이라"). 기대: 탈락마다 이유 질문 한 번, 서류 0/2는 "판단하기 이른 숫자", 두 공고에 공통인 "브랜드 런칭 경험" 갭을 반복 패턴으로 보여주고 반영할지 묻기, 계약직은 관찰로만 기록하거나 dealbreakers에 넣을지 묻기. 커리어 파일에 `outcomes`와 `learnings`가 들어가는지 확인한다.

## 알려진 한계
- 긴 파일은 첫 열람에서 중간이 생략될 수 있다 (2026-10-25 테스트에서 GPT가 다시 열어 보완함). 끝 표시(END) 확인 규칙이 이를 막는다.
- GPT의 웹 검색이 일부 채용 사이트의 상세 페이지를 읽지 못할 수 있다. 그 경우 공고 URL을 붙여넣으면 그 공고로 분석한다.
- 커스텀 GPT는 OpenAI 정책에 따라 종료될 수 있다. 레포가 원본이라 다른 환경에서도 `START.md`로 시작하면 된다.
