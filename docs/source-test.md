# 공고 소스 접근 테스트 (한국)

목적: GPT가 어느 사이트의 공고 **상세 페이지**를 실제로 읽을 수 있는지 확인한다. 판정 대상은 **모집 상태(모집 중/마감), 마감일, 직무·요건, 근무지**다. 게시일은 대부분 읽히지 않으므로 필수에서 뺐다(읽히면 기록만 한다). 한국 공고는 연봉을 "협의"로 쓰고 야근은 적지 않으므로 연봉·야근은 판정에서 제외한다. 읽히는 소스를 `sources.yml`의 앞 순서로 올리고, 막힌 소스는 `blocked`로 표시한다.

## 준비
- 웹 검색을 켠 ChatGPT에서 **새 대화**를 연다 (커스텀 GPT 말고 일반 대화로 먼저. 같은 결과가 나오는지는 나중에 GPT에서 한 번 더 확인).
- 소스마다 아래 프롬프트를 따로 보낸다. 한 대화에 여러 소스를 섞지 않는다.

## 테스트 프롬프트 (소스 이름과 도메인만 바꿔서 사용)

```
{소스 이름}({도메인})에서 "서비스 기획자 서울" 공고를 검색해줘.
상위 3개 공고에 대해 상세 페이지를 직접 열어서 아래를 확인해줘.
열지 못했거나 못 읽은 항목은 추측하지 말고 "읽지 못함"이라고 적어줘.

표로 답해줘:
| 회사 | 포지션 | 상세 페이지 열림(예/아니오) | 게시일 | 마감일 | 주요 요건 한 줄 | 근무지 | 막힌 이유(있으면) |

마지막에 한 줄: 이 사이트는 상세 페이지를 읽을 수 있다 / 일부만 읽힌다 / 읽을 수 없다 중 하나로 판정해줘.
```

대상 소스: 원티드(wanted.co.kr), 사람인(saramin.co.kr), 잡코리아(jobkorea.co.kr), 링크드인(linkedin.com/jobs)

## 정확도 확인 (중요)
GPT가 "읽었다"고 답해도 지어냈을 수 있다. 특히 모든 공고의 마감이 똑같이 "상시채용"이면 읽은 값이 아니라 짐작일 가능성이 높다. 판정이 ok/partial인 소스는 상위 1개 공고를 Jason이 직접 열어서 아래를 대조한다.

| 소스 | 공고 | GPT가 말한 게시일/마감 | 실제 | 일치 |
|---|---|---|---|---|
| | | | | |

## 결과 해석
- 1개 이상 ok: 그 소스를 sources.yml 맨 앞으로. 나머지는 보조.
- 전부 partial/blocked: **URL 붙여넣기를 기본 경로로** 바꾸는 결정을 한다. 제품 성격이 "자동 수집"에서 "내가 고른 공고를 평가"로 바뀐다.
- 정확도 대조에서 불일치가 나오면 그 소스는 ok로 올리지 않는다.

## 새 사이트 추가하기

1. `sources.yml` 맨 위 주석의 형식대로 새 소스를 `status: untested`로 넣는다.
2. 위 테스트 프롬프트에서 소스 이름·도메인을 바꾸고, 검색어를 디자인 직군으로 바꿔 보낸다 (예: "프로덕트 디자이너 서울").
3. 상세 본문이 안 읽히면 원인을 `how_to_read`에 적는다 (예: 별도 프레임, 이미지 본문, 403). 우회 방법은 적지 않는다.
4. 상위 1개 공고를 사람이 직접 열어 모집 상태·마감·요건을 대조한다.
5. 일치하면 `partial`(일부) 또는 `ok`(전부)로 올리고 시도 순서를 정한다. 불일치면 `blocked`.
6. 테스트 날짜와 결과를 `note`에 한 줄 남긴다.
