# 테스트 확인 순서 (test-checklist.md)

규칙을 고친 뒤 이 순서로 확인한다. ChatGPT 일반 새 채팅(웹 검색·코드 실행 켬)이나 Claude에서 한다. **AI의 메모리·과거 대화 참조는 끈다** (예전 규칙이 기억으로 섞인다). 시작 문장은 README의 "시작 문장"에서 주소의 `stable`을 **`main`으로 바꿔** 쓰고, `?t=` 숫자를 매번 바꾼다.

## 0. 읽기·버전

- [ ] "START.md를 읽었으면 마지막 줄을 그대로 적어줘" → `<!-- END: START.md -->`
- [ ] "지금 읽은 규칙 버전이 뭐야?" → START.md의 규칙 버전과 같은 값
- [ ] "어느 브랜치 주소로 파일을 열었어?" → 시작 문장과 같은 브랜치(main 또는 stable)

## 1. 처음 시작 (`examples/sample-conversation-designer.md` + 이력서·자소서)

- [ ] 첫 줄이 privacy_notice 문구 그대로
- [ ] Q1만 묻고 멈춤. Q1에 한국 밖 지역을 답하면 out_of_scope_region 안내
- [ ] Q2가 확인형(이력서에서 읽은 학력 + 포트폴리오 상태)
- [ ] 학교·전공이 대화와 달라도 멈추지 않고 프로필 블록에 "대화·서류와 다름" 표시
- [ ] Q3에 힌트·보기·자소서 내용 없음. 질문 끝에 "미리 찾아본 공고나 꼭 가고 싶은 회사" 한 줄
- [ ] Q3에서 회사 이름이나 공고 링크를 주면 프로필 `targets`에 들어가고, 그 공고가 10개 안에 "★"로 표시
- [ ] 원티드 링크를 주고 브라우저가 없는 환경이면, 검색 전에 jd_paste_request(붙여넣는 방법 3단계)로 멈춤

## 2. 리포트

- [ ] 마감 공고 없음, 1~3위는 모집 중 + 요건을 읽은 공고
- [ ] 리포트 위에 "규칙 v·읽은 파일" 확인 줄이 없음
- [ ] 대조표는 리포트에 없고, 장단점 각 2~3개·맹점 1~2개, 근거 번호 있음
- [ ] "3일 투두" 대신 "먼저 확인할 것"
- [ ] TOP 3 다음에 benefit_report("이번에 해 드린 것: 공고 n개를 확인해…") 한 줄
- [ ] 이름·연락처가 리포트·커리어 파일 어디에도 없음
- [ ] 근거 없는 판단, 읽지 않은 요건 인용, 지어낸 경험이 없음 (보내기 전 점검)
- [ ] 마지막 줄이 strategy_offer

## 3. 지원 전략 (1~3위 중 하나 선택, 포트폴리오 PDF 첨부)

- [ ] 3Q 초안 세 개가 한 번에 나오고 한 번만 멈춤 (근거 포함, 자소서 말투)
- [ ] 요건 확인 질문은 하나씩
- [ ] 포트폴리오는 본 페이지를 밝히고 시각적 완성도를 평가하지 않음 (이미지 전용 PDF로도 한 번)
- [ ] "언제 하실래요?"로 날짜를 받음
- [ ] 끝에 benefit_strategy 한 줄, 커리어 파일에 `story`·`strategy`·`next_actions`

## 4. 이어가기 (커리어 파일만 첨부)

- [ ] 첫 줄 benefit_resume("지난 기록으로 이어갈게요…"), 그 아래 지원 현황 표(관심 단계가 아닌 공고만), 상태 요약 3줄 이내
- [ ] 미확인 행동부터 하나씩, 지원 관련이면 공고별 결과를 메뉴 전에
- [ ] 메뉴 5개(① 지난 가설 점검 ② 공고 다시 찾기 ③ 지원 결과 기록 ④ 자유롭게 물어보기 ⑤ 지원 전략)
- [ ] 반복 근거가 있으면 메뉴 위에 pattern_hint 한 줄만, 패턴 분석은 ③ 뒤
- [ ] ① 가설 점검: 가설마다 확인 행동 결과를 묻고 상태를 바꿈
- [ ] 세션 끝에 benefit_end 한 줄 + 커리어 파일

## 5. 지원 결과·패턴 (`examples/sample-career-file-designer.md`)

- [ ] 탈락·지원 안 함마다 이유 질문 한 번, "모름" 허용
- [ ] 서로 다른 공고 2건 이상에서 같은 요건 갭이면(이유가 "모름"이어도) 묶고, 근거 종류를 나눠 보여줌
- [ ] 동의를 묻고 멈춤. 동의 후 `status: 반영`, `applied_to`는 [검색/채점 근거/전략/가설] 목록, `evidence_detail` 있음
- [ ] 형식에 없는 칸(`user_note` 등)을 새로 만들지 않음

## 배포

- [ ] 위 항목을 `main`으로 모두 통과했다
- [ ] `git push origin main:stable` (사용자 대화에 반영되는 순간)
- [ ] `stable` 시작 문장으로 0번(마지막 줄·버전)만 한 번 더 확인

## 알려진 한계

- 긴 파일은 첫 열람에서 중간이 생략될 수 있다. 끝 표시(END) 확인 규칙이 이를 막는다.
- 원티드·링크드인은 웹 읽기 도구로 막히는 경우가 많다. 브라우저가 없으면 JD 붙여넣기로 간다.
